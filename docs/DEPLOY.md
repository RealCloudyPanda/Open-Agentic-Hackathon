# Static packages for three public origins

No deployment has been performed. The default local workflow remains `npm start`.

Copy `sites.config.json` to a file outside the repository, preserving the three site IDs. Set each site's `publicOrigin` to its own bare HTTPS origin (no path or trailing slash), for example `https://spec-desk.example.test`, `https://test-planner.example.test` and `https://risk-radar.example.test`.

Run `npm run build:static -- --config /absolute/path/to/public-sites.json`. Output defaults to `dist/{spec-desk,test-planner,risk-radar}`. An optional `--out` accepts a directory outside the source tree. The build refuses duplicate IDs, incomplete origins and source-directory outputs. It rewrites peer URLs and visible host labels, reparses canonical networks, regenerates coded-tool SRI and preserves vendored runtime bytes.

Upload each named folder as the root of its matching origin. Apply `_headers` or equivalent hosting configuration: public artifact CORS, JavaScript MIME types (including `.mjs`), `nosniff`, and the sandbox-worker CSP. Do not add provider keys to files or hosting environment variables; default sample mode needs none.

Local verification: `npm test`, `npm run build:networks -- --check`, and `npm run test:e2e`. The packaged browser case serves exact generated bytes through three local HTTPS transport fixtures and exercises relay plus Risk Radar swap. It does not test a hosting vendor, public DNS or deployment header processing. After owner deployment, verify those headers and repeat the complete consent/relay/check/swap flow against the actual URLs before sharing a public demo.
